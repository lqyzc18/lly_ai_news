# 2022-07-01 AI 大事件

北京时间 2022 年 7 月 1 日（星期五）。一条开源治理消息：非营利机构 Software Freedom Conservancy（SFC）发布《Give Up GitHub: The Time Has Come!》，宣布终止自身对 GitHub 的全部使用，并公布长期计划协助自由及开源软件（FOSS）项目迁离 GitHub。博文署期美国时间 6 月 30 日，按北京时间落在 7 月 1 日。

> 本期记 1 条：软件自由保护协会宣布弃用 GitHub，号召 FOSS 项目迁出。

## 1. SFC 宣布弃用 GitHub，并给出四条理由

SFC 在官方博客中发布《Give Up GitHub: The Time Has Come!》，宣布结束自身对 GitHub 的全部使用，并公布长期计划协助 FOSS 项目迁离 GitHub。机构表示不会强制现有成员项目迁移，但不再接受没有长期迁移计划的新成员项目；同时会为选择迁移的成员项目提供资源与支持。

历史类比是文章的开篇。SFC 写道，二十一年前最流行的代码托管站 SourceForge 把全部代码私有化，FOSS 项目逐渐迁出，该站在互联网泡沫破裂后慢慢衰落。二十一年后，FOSS 必须重新学一遍这一课，而这次的对象是微软的 GitHub。

四条主要理由写在专页上。Copilot 是营利性产品，其 AI 模型使用了托管在 GitHub 上、含大量 copyleft 授权的项目；GitHub 托管站本身是专有/商业秘密软件；GitHub 完全由微软所有；社区贡献者从未获得相应话语权。

导火索是与微软、GitHub 长达一年的沟通没有结果。SFC 自 2021 年 7 月 Copilot 刚推出时起就提出三个问题：在训练机器学习系统于公开数据上是否属于合理使用、输出是否像编译器产物一样归运营者所有，以及训练集究竟包含哪些许可证与哪些代码仓库的副本。首次视频会议后对方承诺「很快答复」，六个月毫无回应；SFC 发表公开文章后 GitHub 仍不答；对方邀请微软与 GitHub 参加公开讨论被拒绝。SFC 随后收到回复：既然 GitHub 认为关于 AI 辅助软件的伦理「不太可能改变你们的立场」，就不作答复。

SFC 的判断是，这本身就构成答案。SFC 认为，如果真如对方所说可以在任何代码上训练模型而不受许可证约束，那为什么只挑 FOSS 来训练，为什么不把微软自己的 Windows 与 Office 代码库放进去。

行动方案已经铺开。SFC 启动了 GiveUpGitHub.org 专页，提供迁移的方法、工具与支持，并计划公布更多自建托管实例选项、以及用 GitLab Community Edition 自行部署的指南。文中还提到基于 Gitea 的 CodeBerg 已实现 GitHub 的大部分功能。

背景是同一周的另一件事：GitHub 宣布 Copilot 作为商业收费产品正式发布。SFC 说，在此之前 Copilot 更像研究原型而非产品，「事实变了」。

**★ 本次特有的新发现**
1. **同一事件有两个官方时刻时，用早的「公开时刻」定归属日、正文同时披露另一时刻**；次日篇只交叉引用、不得重写。Gemini Robotics 2.5 的官方 RSS pubDate ＝ 11-09 19:51Z（＝北京 11-10 03:51）⇒ 归 11-10 篇；而官方页标注的模型上线时刻 11-10 15:00Z（＝北京 11-10 23:00）落在次日篇窗口内。Gemini 4 Carbon 的 pubDate ＝ 11-10 16:03Z（＝北京 11-11 00:03）⇒ 归 11-11 篇。**中文报道写的「11 月 10 日」是美东日期，不能当北京时间。**
2. **MDX 发前用脚本预检最省返工**（脚本：`/workspace/ai_daily/check_mdx_1110.py`）：标签配平 / 颜色 token 白名单（三张分开校验）/ 块级组件必须三段式多行 / 图标总数 ≤15 / frontmatter 字段白名单 / 禁 `**` 与 `{}` / 正文禁与 frontmatter title 同名的一级标题。**预检 0 fail 再 create→move→点验**，避免整篇创建失败后重写。
3. **GitHub 日报 lane 的 5 处动态位**可用正则一次改完：README badge「最新-YYYY--MM--DD」与「日报-N%20篇」、README「## 最新」节、README「## 归档」当年行、ARCHIVE.md 当月行；篇数 N 用 git trees API 递归数 `YYYY/MM/YYYY-MM-DD.md`。**注意 badge 里是 `%20` 不是 `%2520`。**
4. **GitHub contents API 的 PUT 必须显式 `method="PUT"`**：给了 body 却没写 method 时 urllib 默认发 POST，打 `/contents/{path}` 返回 **404 Not Found**，极易误判成「权限/路径不存在」（token 有 admin 也照样 404）。

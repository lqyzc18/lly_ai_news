## 三、提交方式：git 协议（不占 GitHub REST 配额）
**REST 限额 5000/hr 是全用户共享的，多路并发会瞬间打爆（全 403）。`git push` 走 git 协议，不消耗 REST 限额。**
```bash
cd /workspace/repo_cron
git config --global user.email "lqyzc18@users.noreply.github.com"
git config --global user.name  "lqyzc18"
git config --global http.sslCAInfo /etc/ssl/certs/agent-identity/sandbox-gateway-ca.crt
git config --global credential.helper '!f() { echo username=x-access-token; echo password=$GITHUB_TOKEN; }; f'
# 每篇一个 commit：
git add YYYY/MM/YYYY-MM-DD.md
git commit -m "Add the {Month DD, YYYY} AI news digest."
git push origin HEAD:main
```
- **push 被拒**（`! [rejected] ... (fetch first)`）→ `git pull --rebase origin main` → 再 push。
- **不用管 sha**；改已有文件就直接改工作区再 add/commit/push。
- **目录按年/月两级**（`2024-04-30.md` → `2024/04/2024-04-30.md`）。
- ⚠️ **绝对不要 `rm -f .git/index`**（锁释放不了说明有别的进程在用 git，等 5~10 秒重试）。push 前 `git diff --cached --stat` 自检暂存区；commit 后 `git show --stat HEAD` 核对只动了 1 个文件。
- ⚠️ **push 前必须跑 `python3 /workspace/verify_mid.py --dir <你的输出目录> <日期...>`**（U+FFFD / 节数 / 字数 / 正文 arXiv id 是否在来源里 / 篇内 URL 重复 / 缺 `## 来源`）。**不跑不许推。**
- ⚠️ **Write 写长中文会偶发单字损坏**（3 个 U+FFFD 顶掉 1 个汉字）→ 优先用 Edit 做局部修改；写完用 python `t.count('\ufffd')` 扫（**bash 的 `grep $'\ufffd'` 在这沙箱检不出来**）。
- ⚠️ **批量并行修改必须走内存 dict，中途绝不重读磁盘**；写盘用临时文件原子替换；逐条校验「源文件命中 0 + 目标文件命中 1」；出错用 `git show <commit>^:<path>` 恢复原文。
- ⚠️ bash 默认 30 秒超时 → 长任务用 `run_in_background=true` 或显式传 `timeout`。

## 四、归日口径（全档唯一，不得自选）
> **以发布方的发布时间为准：事件公开那一刻换算成北京时间落在哪一天，就归哪一天。正文标注发布方的原始发布时间。**

**① 有精确时刻就用精确时刻换算。**（官方页 JSON-LD 非零时分 / RSS pubDate / 法院文件时间戳 / GitHub 首个 commit `created_at` / arXiv 公告批次 / 媒体首发稿精确时刻 / X 帖 snowflake 解码 `ms = (id >> 22) + 1288834974657` / 期刊 Crossref `published-online`）
**② 只有日期没有时刻，才按「发布方当地日期 + 1 天」保守处理**（美国厂商多在美国工作日白天 = 北京当日深夜到次日；**中国机构按当地日，不 +1**），正文注明依据是「官方标注日」。
**③ ⚠️ OpenAI / Anthropic 官方页与 RSS 的 `datePublished` 被归一化到太平洋零点**（全年只有固定几个值），**只能定当地日，不可当真实时刻**。
**④ 同一事件有多条一手公开时刻 → 取最早的那条。**
**⑤ ⚠️ 但「开源代码仓库的 `created_at`」≠「成果披露日」** —— 实测 FunSearch 官方仓库 11-23 上线、论文与官方博客 12-14 才披露成果 → **归 12-14，仓库上线日只在正文注明**。
**⑥ 论文与技术报告**：早于作品发布（读者提前能读到）→ 独立成日；晚于作品发布超一周（只是补技术报告）→ 只在正文注明；相差一周内 → 各渠道可分日。
**⑦ 中文转载日不作归属依据**（通常比事件日晚 1~2 天）；**不按「每日早报」的日期落笔**；**官方页面的日期会被事后改写**。
**⑧ 允许建清单外的日期**，在汇报里单列。
**⑨ 范围**：模型发布、公司与产品、监管与政策、开源与算力基础设施、资本与人事。**诺奖类、纯数学奖不收。**

### ★ arXiv 归日：官方公告排期（**不要用「v1 提交日 + 1」**）
官方排期（`info.arxiv.org/help/availability.html`）：提交截止 **14:00 ET**；公告 **20:00 ET**（= 北京次日 08:00/09:00）；**"posted publicly Sunday through Thursday, with no announcements Friday or Saturday"**。
- 周一~周四 14:00 ET 前提交 → 次日（周二/三/四/五）；周一/二/三 14:00 后 → +2；**周四 14:00 后 → 下周一**；**周五 → 下周一或下周二**；**周六/周日 → 下周二**。
- **⇒ 「v1+1」只在周一~周四 14:00 ET 前成立。北京时间【周六、周日】没有 arXiv 新论文 —— 若算出某条归在周末，一定错了。**
- **工具**：`python3 /workspace/arxiv_batch.py --ids <id1,id2>` → 输出 `v1_utc | ET 时刻 + before/after | 北京归日`（**内部已含 zoneinfo DST，照它算，别自己写偏移表**）。
- **OAI `<datestamp>` 只作旁证**（多版本论文的 datestamp 是最新版日期；仅 v1 的记录里约 1/4 后来被改过，会比真实归日晚一天）。不一致一律以排期表为准。
- **arXiv OAI 必须带 `-L`**：`https://export.arxiv.org/oai2?...` 会 302 到 `oaipmh.arxiv.org/oai`，**不带 `-L` 就是 0 字节、容易误判成「当天没论文」**。`<created>` 是最新版提交日不是 v1。

## 六、写作格式与质量标尺
格式照远端 `2026/10/2026-10-19.md`（用户已验收的定版稿）：标题行 → 「北京时间 YYYY 年 M 月 D 日（星期X）。」导语 3~5 句 → `## 1. 主体：要点` 分节 → `## 来源` 每条一行 `- [名称](url)`。
**⚠️ 仓库没有尾注规范 —— 定版稿结尾就是来源列表最后一行，不要加 `Co-authored-by`。**

**质量标尺（对定版稿 49 篇实测重定，不要自创更严的数字）**：
- **硬下限 1200 字符**（低于此 = 残缺稿，必须处理）；**目标 ≥1800**；**1200~1800 属正常分布 → 不许注水**（定版稿 202609 月中位仅 1355、28/30 篇低于 1800）
- **每篇 2~8 节**（202610-18/19 是 8 节，用户验收过）；**每节 2~6 段**（**2 段是定版稿常态**，202609 有 28 处）；**段落长度不设硬线**；**不允许用 1 段成节**
- **「无达标事件日」是另一种形态**：**300~1000 字符**，必须写明「本日无达标事件」+ 一节说明检索了哪些维度、为什么判定不足 + `## 来源` 列真实检索依据 URL
- **「补厚」= 补一手来源、补具体数字、补官方原话，不是把段落拉长。**
- 金额/评测数字标明出处（公司自述 / 媒体引述）；未经证实写「据报道」；**正文同时标注「事件日」和「报道日」**；来源 URL 必须真实抓到、不得编造，至少 2 条。
- 中文，严谨克制，结论先行，专有名词保留英文原文。不要 emoji，不要营销号词汇。

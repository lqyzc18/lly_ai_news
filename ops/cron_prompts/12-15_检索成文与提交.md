## 二、检索与核实
- 检索至少覆盖：头部模型（OpenAI、Anthropic、Google、Meta、xAI、DeepSeek、阿里、字节、智谱、月之暗面）、算力与芯片（NVIDIA、AMD、谷歌 TPU、华为）、监管与诉讼、产业与产品（Agent、具身智能、AI 编码）、资本与人事。**英文 + 中文各至少一轮**，用 `web_search`（`freshness` 设 `day`），必要时用 `web_fetch` 抓原文。
- **判定日期必须回到官方渠道**：公司官网/官方博客/API 更新日志/法院文件/监管公告/通讯社电头/官方 X 帖。聚合站只用来发现线索。
- **判定优先级**：原文 URL 里的日期路径 > 通讯社电头 > 官方博客/newsroom > 权威媒体首发 > 聚合站时间戳 > 中文转载日。
- **中文媒体说「10 月 17 日 X 报道了 Y」，几乎总是指中文稿日期，不是 X 的发布日期。**
- 聚合站经常把旧闻当当日头条重推。相对日期（周四、下周一、近日）必须换算成绝对日期再比对。
- **未来事件只能写成预告**，不能写成已发生。
- 未经公司证实的说法标「据报道」；**无法回到官方渠道判定的条目直接丢弃，宁缺毋滥**。
- 金额、评测数字来自公司自报或媒体引述，**直接标明出处，不要自行核实原始评测**。

### 五条会反复踩的归日规则
1. **官方页面的日期会被事后改写**（实测 NVIDIA NeMo Parakeet 的博客页 datePublished 变成了 4/18，真实是 1/3 发布）。用页面日期判「发布日」会出错 —— 找精确时刻旁证（RSS、arXiv v1、仓库首提、法院文件），核不回来就剔除该条。
2. **OpenAI 官方 RSS**（`openai.com/news/rss.xml`）可直接 curl，每篇 blog 带精确到分的 GMT pubDate，判 OpenAI 事件归日最省事。**⚠️ 但 pubDate 落在 00:00:00 GMT 的是「太平洋零点归一化」值，不是真实时刻**，这种条目按「官方标注日 + 1 天」处理；带真实时刻的按时刻折算。RSS 里也偶有老文章被重发（2023 年的 GPT-4 API GA 被标成 2024-04-24），逐条核对不采用。
3. **arXiv v1 的公开时刻 ≠ 提交时刻**：arXiv 每日 14:00 ET 截止、20:00 ET 公布，提交日 D 对应北京时间 D+1 08:00 → **归 D+1**。**⚠️ arXiv OAI 的 `<datestamp>` 有地雷**：`http://export.arxiv.org/oai2?verb=GetRecord&identifier=oai:arXiv.org:<id>&metadataPrefix=arXiv` 返回的是**记录里最新版本**的公布日，**只有「仅 v1」的论文才等于 v1 公布日**（实测 2403.14773 有 v2，datestamp 返回 2025-04-17，差了 13 个月）。用之前先 `curl -sL https://arxiv.org/abs/<id> | grep -oE '\[v[2-9]\]'` 查有无后续版本。`export.arxiv.org/api/query` 在本沙箱返回空，用 `arxiv.org/abs/<id>`。
4. **X 帖 snowflake ID 解码**：`ms = (id >> 22) + 1288834974657` → UTC 毫秒，秒级精确，是钉美东发布日最可靠的办法。
5. **凡来源日期落在「稿件日 − 1」的官方页、且没有更强时刻证据的，一律按「官方标注日 + 1 天」复查。**

## 三、归档口径（决定归哪一天）
- **以发布方的发布时间为准，落到北京时间那一天。** D 日的稿覆盖「北京时间 D 日 00:00–12:00」+「美东 D-1 日 11:00–23:59」（12:00 北京 = 00:00 美东）。
- **美东 D-1 日下午到深夜的发布归 D 日**。12:00 截稿时它们已经发生，只是还没被写进 D-1 的笔记。**D-1 日下午和夜里的内容要主动去找**，不能只搜「今天」——这是历次漏稿的主要来源。
- **校准锚点**：太平洋 10:00 = 北京当日 02:00 → 归**当日**；太平洋 12:00 之后 = 北京次日 → 归**次日**。
- 同一条事件官方页与媒体稿都有的，取**更早的那一个**（通常是官方），用它的时刻定日。
- 正文里必须写出事件的**原始发布时间**（美东 X 日下午/夜间发布写「美东 X 月 X 日」或「X 月 X 日晚间」）。

## 五、成文

### 5.1 写文件的两步
1. contents API 取目标路径的当前内容与 sha（返回 404 = 当天文件不存在，直接走新建）。
2. `PUT https://api.github.com/repos/lqyzc18/lly_ai_news/contents/<路径>` 写入，body `{"message":"<commit message>","content":"<base64(utf-8 正文)>","branch":"main","sha":"<已有文件的 sha>"}`。**一次 PUT = 一个 commit**；文件已存在必须带 `sha`，否则 422。

日报、README、ARCHIVE.md 是三个文件，分三次提交：
- 日报 commit message 用 `Add` 开头；确属补录则用 `Extend` 开头。
- README commit message 用 `Refresh the latest section in the README.` 开头。
- ARCHIVE.md commit message 用 `Refresh the monthly index in ARCHIVE.md.` 开头。
- message 用英文，正文一行写清记了哪几条。
- **⚠️ 2026 段不加 `Co-authored-by` 尾注**（实测 9-10 月 19 篇定版稿均为 0 尾注；3 月、8 月带尾注是历史回填遗留，不要给新写的 2026 稿加）。2022-2025 回填段按当时 majority 决定。

### 5.2 目录结构（2026-10-20 起）
日报按**年/月两级**存放：`YYYY/MM/YYYY-MM-DD.md`（例 `2026/10/2026-10-19.md`）。**不再是扁平的 `202610/`。** 目录名由日期推出：2026-10-20 → `2026/10/`。

### 5.3 当天文件的三种情况
动笔前先读 `YYYY/MM/YYYY-MM-DD.md`。
- **不存在 → 从零生成一篇完整的新日报。** 正常路径。
- **已存在 → 走补录路径**，先通读找缺口，只补没有的部分，不要重写整篇。
- **竞态防护**：写文件前再读一次 SHA，防止覆盖别人刚推的版本。Cursor 端已于 2026-10-18 停用，不再是事实上的竞态源。

### 5.4 格式（照仓库现有文件写，风格要一致）
- 第一行标题：`# YYYY-MM-DD AI 大事件`
- 第二段导语：`北京时间 YYYY 年 M 月 D 日（星期X）。` 开头，用 3~5 句把当天主线点完。
- 分节：`## 1. 主体：要点`，每节 3~4 个自然段，写清时间（协调世界时/美东时间换算成北京时间也标一句）、原文引语、具体数字。**公司的自述要与记者的核实分开写。**
- 结尾：`## 来源`，每条一行 `- [名称](url)`，**URL 必须来自素材里给的原文地址，不要编**。
- 整体中文，严谨克制，结论先行，专有名词保留英文原文。不要营销号词汇，不要 emoji。
- 范围：模型发布、公司与产品、监管与政策、开源和算力基础设施，资本与人事。纯研究进展也要，但得有具体结果和出处。
- **日期交代**：素材里标了「归属窗口」和「原始发布日」的，正文里要体现出来。**晚于当天中午的笔记、补录的事件，正文里注明「……早于当天中午的笔记，当时没有写入，补在这里」或「……美东 X 月 X 日下午发布，晚于 X 日中午的笔记，因此记在今天」。**
- **归日口径**：一篇文件只写「按北京时间落在当天」的事件，判据是事件公开那一刻的时刻。**自己核过归日就按自己核的写；没核过就不要写。**

**质量标尺（以用户验收过的定版稿实测分布为准，不要自创更严的数字）**：
- **每篇 ≥ 1800 字符**（已验收定版稿篇均 2371 字符；10-18.md 实测 18313 字符，含 8 节）
- **每篇 2~8 节**（2026-10-18/19 是 8 节，9-30 也是 8 节 —— **不要把 5 节当硬上限**）
- **每节 2~4 段**（**2 段是定版稿常态**，202609 有 28 处；不是每节必须 3~4 段）
- **段落长度不设硬线**，中位 110~130 字符即可（定版稿段落中位实测仅 108 字符，只有 24% 达 180 字符 —— **不要按「每段 ≥180 字符」去灌水**）
- **不允许用 1 段成节** —— 1 段成节读起来像提纲不像日报
- 素材撑不起 2 节就写短篇，**别为凑节数注水**；但也**别写成只有 1 段的一节**

## 六、异常
- **REST 调用超时 / 5xx / 连接重置**：重试 2~3 次，间隔 10 秒。**不要因为连接器不可用就放弃 GitHub 读写——REST 通道是通的。**
- **写文件失败**（REST 不通、返回体解析不出 sha）：如实报告失败原因，**不要声称已提交**。
- **Token Plan 额度耗尽**：会话秒级结束、无产出 = 第一轮模型调用就被打回。这**不是限流也不是连接器问题**，重试无意义。立刻停止，如实说明「额度耗尽，本次未产出」。
- **检索完全失败**（网络搜索全挂）：诚实说明，**禁止凭记忆编造**。
- **素材为零**（一条候选都没有）：如实告诉用户「今天没有达到归档标准的重大事件，本次不产出日报」，不要硬凑。
- 写完自查：读回当天文件，确认节数、来源列表与正文条数大致对得上；再读回 README，确认版式没被改散、badge 日期和篇数已更新。

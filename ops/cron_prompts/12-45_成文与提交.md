## 三、成文
### 3.1 仓库读写（**GitHub Connector 整片不可用，走 REST**）
- 仓库 lqyzc18/lly_ai_news，默认分支 main。**`connector__github__*` 一律不可用**（`invalid_provider` / `tool_name ... is not available`），不要调用；下面给的是 REST 等价写法。
- 读文件正文 → `curl -sL "https://raw.githubusercontent.com/lqyzc18/lly_ai_news/main/<路径>"`。
- 读文件 + 取 blob sha → `curl -s -H "Authorization: token $GITHUB_TOKEN" "https://api.github.com/repos/lqyzc18/lly_ai_news/contents/<路径>"`，sha 就是 `d["sha"]`（文件不存在时返回 404 = 当天文件不存在）。
- 写文件 → REST `PUT https://api.github.com/repos/lqyzc18/lly_ai_news/contents/<路径>`，body `{"message":"<commit message>","content":"<base64(utf-8 正文)>","branch":"main","sha":"<已有文件的 sha>"}`。**一次 PUT = 一个 commit**；文件已存在必须带 `sha`，否则 422。
- 看提交 → `curl -s -H "Authorization: token $GITHUB_TOKEN" "https://api.github.com/repos/lqyzc18/lly_ai_news/commits?path=<路径>"`。
- **REST 返回都是普通 JSON，一次 `json.loads` 即可**（没有连接器那种双重 JSON 包裹）。

### ⚠️ 目录结构（2026-10-20 起）
日报按**年/月两级**存放：`YYYY/MM/YYYY-MM-DD.md`（例 `2026/10/2026-10-19.md`）。**不再是扁平的 `202610/`。** 目录名由日期推出：2026-10-20 → `2026/10/`。

### 3.2 当天文件的三种情况
动笔前先读 `YYYY/MM/YYYY-MM-DD.md`（当天那篇，例 `2026/10/2026-10-20.md`）。
- **情况 A：不存在 → 从零生成一篇完整的新日报。** 正常路径。
- **情况 B：存在且作者是 `Cursor Agent <cursoragent@cursor.com>`（用 commits API 确认）→ 当草稿**：逐条核实素材与它的关系 → 补上遗漏的重要事件 → 用带 `sha` 的 PUT 更新，**禁止整篇覆盖重写**。commit message 用 `Extend`。正文里注明补录条目的原始发布日与出处。
- **情况 C：存在且是你上一次运行写的（重跑）→ 同样走补录路径**，先通读找缺口。

**竞态防护**：Cursor 端在 12:0X 提交，你排期在 12:45。写文件前再读一次 SHA，防止覆盖别人刚推的版本。

### 3.3 写文件的两步
1. contents API 取目标路径的当前内容与 sha（返回 404 = 当天文件不存在，直接走新建）。
2. `PUT` 写入（body 带 `message` / `content`（base64）/ `branch: "main"`，已有文件再加 `sha`）。
日报、README、ARCHIVE.md 是三个文件，分三次提交：
- 日报 commit message 用 `Add` 开头；确属补录则用 `Extend` 开头。
- README commit message 用 `Refresh the latest section in the README.` 开头。
- ARCHIVE.md commit message 用 `Refresh the monthly index in ARCHIVE.md.` 开头。
- message 用英文，正文一行写清记了哪几条，结尾固定加：
  `Co-authored-by: lqyzc18 <lqyzc18@users.noreply.github.com>`

### 3.4 格式（照仓库现有文件写，风格要一致）
- 第一行标题：`# YYYY-MM-DD AI 大事件`
- 第二段导语：`北京时间 YYYY 年 M 月 D 日（星期X）。` 开头，用 3~5 句把当天主线点完。
- 分节：`## 1. 主体：要点`，每节 3~4 个自然段，写清时间（协调世界时/美东时间换算成北京时间也标一句）、原文引语、具体数字。**公司的自述要与记者的核实分开写。**
- 结尾：`## 来源`，每条一行 `- [名称](url)`，**URL 必须来自素材里给的原文地址，不要编**。
- 整体中文，严谨克制，结论先行，专有名词保留英文原文。不要营销号词汇，不要 emoji。
- 范围：模型发布、公司与产品、监管与政策、开源和算力基础设施，资本与人事。纯研究进展也要，但得有具体结果和出处。
- **日期交代**：素材里标了「归属窗口」和「原始发布日」的，正文里要体现出来。**晚于当天中午的笔记、补录的事件，正文里注明「……早于当天中午的笔记，当时没有写入，补在这里」或「……美东 X 月 X 日下午发布，晚于 X 日中午的笔记，因此记在今天」。**
- **归日口径**：一篇文件只写「按北京时间落在当天」的事件，判据是事件公开那一刻的时刻。素材已把归日核好，你只按素材的「原始发布日」与「归属窗口」写，**不要自己改判**。素材若标注了某条事件属于前一窗口，正文就照它的说明写。

**质量标尺（以用户验收过的定版稿实测分布为准，不要自创更严的数字）**：
- **每篇 ≥ 1800 字符**（已验收定版稿篇均 2371 字符）
- **每篇 2~5 节**
- **每节 3~4 段**
- **段落长度不设硬线**，中位 110~130 字符即可（定版稿段落中位实测仅 108 字符，只有 24% 达 180 字符 —— **不要按「每段 ≥180 字符」去灌水**）
- **不允许用 1 段成节** —— 1 段成节读起来像提纲不像日报
- 素材撑不起 2 节就写短篇，**别为凑节数注水**；但也**别写成只有 1 段的一节**

## 四、异常
- **素材缺失或日期不匹配** → 如实告诉用户「今天的素材没生成（第一段未成功），本次不产出日报」，说明你查了哪里。**不要凭空写稿。**
- 任何一步失败（写文件失败、REST 调用不通、返回体解析不出 sha）：**如实报告失败原因**，不要声称已提交。可重试 2~3 次。
- **Token Plan 额度耗尽**：会话秒级结束、无产出 = 第一轮模型调用就被打回。这**不是限流也不是连接器问题**，重试无意义。立刻停止，如实说明。
- 写完自查：读回当天文件，确认节数、来源列表与正文条数大致对得上；再读回 README，确认版式没被改散、badge 日期和篇数已更新。

### 五条会反复踩的归日规则
1. **官方页面的日期会被事后改写**（实测 NVIDIA NeMo Parakeet 的博客页 datePublished 变成了 4/18，真实是 1/3 发布）。用页面日期判「发布日」会出错 —— 找精确时刻旁证（RSS、arXiv v1、仓库首提、法院文件），核不回来就剔除该条。
2. **OpenAI 官方 RSS**（`openai.com/news/rss.xml`）可直接 curl，每篇 blog 带精确到分的 GMT pubDate，判 OpenAI 事件归日最省事。**⚠️ 但 pubDate 落在 00:00:00 GMT 的是「太平洋零点归一化」值，不是真实时刻**，这种条目按「官方标注日 + 1 天」处理；带真实时刻的按时刻折算。RSS 里也偶有老文章被重发（2023 年的 GPT-4 API GA 被标成 2024-04-24），逐条核对不采用。
3. **arXiv v1 的公开时刻 ≠ 提交时刻**：arXiv 每日 14:00 ET 截止、20:00 ET 公布，提交日 D 对应北京时间 D+1 08:00 → **归 D+1**。**⚠️ arXiv OAI 的 `<datestamp>` 有地雷**：`http://export.arxiv.org/oai2?verb=GetRecord&identifier=oai:arXiv.org:<id>&metadataPrefix=arXiv` 返回的是**记录里最新版本**的公布日，**只有「仅 v1」的论文才等于 v1 公布日**（实测 2403.14773 有 v2，datestamp 返回 2025-04-17，差了 13 个月）。用之前先 `curl -sL https://arxiv.org/abs/<id> | grep -oE '\[v[2-9]\]'` 查有无后续版本。`export.arxiv.org/api/query` 在本沙箱返回空，用 `arxiv.org/abs/<id>`。
4. **X 帖 snowflake ID 解码**：`ms = (id >> 22) + 1288834974657` → UTC 毫秒，秒级精确，是钉美东发布日最可靠的办法。
5. **凡来源日期落在「稿件日 − 1」的官方页、且没有更强时刻证据的，一律按「官方标注日 + 1 天」复查。**（这条是全库 479 篇普查总结出来的，抓到过 DALL·E API 与 Point-E 两例。）

## 三、归档口径（决定归哪一天）
- **以发布方的发布时间为准，落到北京时间那一天。** D 日的素材覆盖「北京时间 D 日 00:00–12:00」+「美东 D-1 日 11:00–23:59」（12:00 北京 = 00:00 美东）。
- **美东 D-1 日下午到深夜的发布归 D 日**。12:00 截稿时它们已经发生，只是还没被写进 D-1 的笔记。**D-1 日下午和夜里的内容要主动去找**，不能只搜「今天」——这是历次漏稿的主要来源。
- **校准锚点**：太平洋 10:00 = 北京当日 02:00 → 归**当日**；太平洋 12:00 之后 = 北京次日 → 归**次日**。
- 同一条事件官方页与媒体稿都有的，取**更早的那一个**（通常是官方），用它的时刻定日。
- 每条素材都要写清它属于哪个时间窗口，以及原始发布日期。

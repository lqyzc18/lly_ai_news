# 2026-01-15 AI 大事件

北京时间 2026 年 1 月 15 日（星期四）。开源模型与硬件的进度同时被推到一个新位置。1 月 14 日，智谱联合华为开源图像生成模型 GLM-Image，宣称这是首个在国产芯片上完成从数据预处理到大规模训练全流程的 SOTA 多模态模型。1 月 13 日，Anthropic 推出 Claude Cowork，把 Claude Code 的代理能力交给非技术用户，而这款工具的第一个版本本身就是 Claude 用十天写出来的；同一天，Google 发布开源医疗模型 MedGemma 1.5 与语音模型 MedASR，把三维影像解析和临床听写一起推进。硬件侧，1 月 14 日有报道称 OpenAI 正开发代号 Sweetpea 的耳后佩戴式 AI 音频设备，首年目标产量 4000 万至 5000 万台。

## 1. 智谱联合华为开源 GLM-Image，首个全流程跑在国产芯片上的 SOTA 多模态模型

智谱 AI 1 月 14 日宣布联合华为开源新一代图像生成模型 GLM-Image。智谱称，这是首个基于国产芯片完成全流程训练、性能领先的多模态模型：从早期的数据预处理到最终的大规模预训练，训练全程在昇腾 Atlas 800T A2 设备上完成，框架为昇思 MindSpore AI，验证了在国产全栈算力底座上训练前沿模型的可行性。模型已在 GitHub、Hugging Face（zai-org/GLM-Image）与魔搭社区开源，并提供在线体验平台。

架构上，GLM-Image 采用"自回归 + 扩散解码器"混合结构，总参数 160 亿：其中 90 亿参数的自回归模块由 GLM-4-9B-0414 初始化，负责语义理解并生成语义 VQ token；70 亿参数的 DiT 扩散解码器负责像素级还原，训练使用 flow matching。智谱把这次发布定位为面向"以 Nano Banana Pro 为代表的新一代认知型生成"技术范式的一次探索，主打海报、PPT、科普图等知识密集型场景与中文文字渲染。

成绩均为智谱自报。CVTG-2K 榜单上，GLM-Image 词准确率 0.9116、NED 0.9557，高于 Seedream 4.5 的 0.89/0.94 与 Qwen-Image-2512 的 0.87/0.92；LongText-Bench 上中文 0.9788、英文 0.9524，超过 FLUX.1 与 SD3.5。通过改进 Tokenizer 策略，模型原生支持 1024×1024 至 2048×2048 的任意比例图像生成且无需重新训练，API 模式下每张图调用成本低至 0.1 元。

外部评价呈现两面。The Register 指出，昇腾芯片在原始算力与内存带宽上仍落后于英伟达 GPU，这限制了模型规模的上限；MindSpore 生态相较 CUDA 尚不成熟，海外团队需要额外适配。英伟达 CUDA 生态能否被替代，最终仍取决于能否扩展到十万卡量级的集群——这一点目前尚未被验证。国产全栈从"能不能训"走向"能训多大"，是这次发布真正的分水岭。

## 2. Anthropic 推出 Claude Cowork，第一个版本由 Claude 自己写出

Anthropic 1 月 13 日推出 Claude Cowork，一款嵌入 macOS 版 Claude 桌面应用的自主代理助理，目标是让非开发者也能用自然语言驱动代理完成多步任务。它以研究预览形式推出，初期仅向 Claude Max 订阅者开放（月费 100 至 200 美元）。Cowork 的定位是 Claude Code 的简化版：共享核心引擎，但把命令行换成自然语言界面，聚焦文件管理与办公自动化。

能力上，用户可以用自然语言指令让 Cowork 访问指定文件夹并执行多步任务，例如自动整理下载目录、根据截图生成表格、从零散笔记起草报告，或控制浏览器做网页检索、整理邮件。它会先制定计划、并行执行任务并持续回报进度。安全边界相对明确：只访问用户明确指定的文件夹并需要授权，重要动作前请求确认，继承了 Claude 的连接器能力（Google Drive、浏览器扩展等）。WIRED 的测评认为它在文件管理与基础计算任务上表现可靠，但作为 beta 产品仍需要用户监督以避免误操作。

更受关注的是它的开发过程。Anthropic Claude Code 负责人 Boris Cherny 在 X 上称，整个工具基本由 Claude Code 构建，开发周期约一周半；工程师 Felix Rieseberg 在直播中确认，这一速度来自"vibe coding"模式——工程师给高层指令，Claude Code 负责生成、调试与优化代码，从文件 API 集成到界面逻辑大部分由它完成。Dario Amodei 在公司博客中把这种模式称为"AI 代理未来"的一个预览，指向人类指导之下的 AI 自治。行业侧的解读更直接：Axios 认为 Cowork 可能冲击 Notion、Airtable 一类文件管理工具的 AI 扩展业务，也把"vibe coding"从一种偏好推成了一种行业动向。值得注意的是，Anthropic 随后在 1 月 16 日把 Cowork 开放给 Pro 订阅用户，此前则一直限于 Max。

## 3. Google 发布 MedGemma 1.5 与 MedASR，开源医疗 AI 同时补上影像与语音

Google 研究院 1 月 13 日发布两支开源医疗模型。MedGemma 1.5 是 MedGemma 家族的一次升级，本次放出 4B 参数版本，基于 Gemma 3 架构、decoder-only Transformer 加分组查询注意力，同时保留此前的 27B 版本用于更复杂的文本任务；MedASR 是新发布的医疗场景专用语音转文本模型。两者均以免费许可供研究与商用，通过 Hugging Face 与 Google Cloud 的 Vertex AI 提供。

MedGemma 1.5 4B 的主要变化是首次支持高维医疗数据：CT 与 MRI 的三维体数据，以及全玻片病理图像，可将多个切片或多个图块连同任务提示一起输入。按 Google 自报的内测结果，疾病相关 CT 发现分类的基线绝对准确率从 58% 提升到 61%，MRI 发现分类从 51% 提升到 65%；病理切片任务的 ROUGE-L 从 0.02 跃升到 0.49，与任务专用的 PolyPath 模型（0.498）基本持平。文本侧，MedQA 从 64% 提升到 69%，EHRQA 从 68% 提升到 90%，实验室报告结构化抽取的检索宏 F1 从 60% 提升到 78%。此外，Google 同期在 Kaggle 上启动奖金 10 万美元的 MedGemma Impact Challenge。

MedASR 是一个 1.05 亿参数的 Conformer 模型，用约 5000 小时去标识化医疗语音训练，覆盖放射科、内科与家庭医学等专科。据 Google 披露，在胸部 X 光听写上其词错误率为 5.2%，低于通用模型 Whisper large-v3 的 12.5%（错误减少 58%）；在内部多专科听写基准上为 5.2%，对比 Whisper 的 28.2%（错误减少 82%）。模型支持 16kHz 单声道音频，可在消费级显卡（如 8GB 显存的 RTX 4060）本地运行，Apache 2.0 许可。谷歌明确声明，MedASR 的输出属"初步结果"，需临床验证，不能直接用于诊断或治疗决策。

实际采用方也在同步推进：马来西亚 Qmed Asia 把 MedGemma 接入 askCPG，用以对话方式查询该国 150 余项临床实践指南；台湾地区全民健康保险署则用 MedGemma 从 3 万余份病理报告中抽取结构化数据，评估肺癌手术术前状况。4B 的体量之所以被强调，是因为它足够小到可以在院内服务器甚至医生工作站上离线运行，满足"数据不出院"的合规要求。

## 4. OpenAI 消费级硬件 Sweetpea 曝光，官方尚未确认

据财联社 1 月 14 日报道，一名网名"智慧皮卡丘 Smart Pikachu"的供应链人士称，OpenAI 正开发一款对标苹果 AirPods 的人工智能设备，内部代号 Sweetpea，预计今年 9 月发布，第一年产量 4000 万至 5000 万台。报道明确指出，这位爆料者此前关于苹果产品的多条消息均未得到证实，OpenAI 是否真的会推出 Sweetpea 仍需进一步验证。

按报道描述，设备主体为金属材质、外形似鹅卵石，充电盒打开后是两个胶囊状设备，可取出佩戴在耳后。硬件上预计采用 2 纳米制程的智能手机芯片，三星 Exynos 为首选方案，另有一颗已开发完成的定制芯片；由于用料与组件和智能手机接近，预计成本相当高。富士康被告知提前准备生产，包括耳机和触控笔在内的五款设备将在 2028 年第四季度前完成，Sweetpea 排在优先生产的位置。OpenAI 此前曾考虑由立讯精密承制，最终选择富士康。功能方面，市场预期它能拨打电话、播放音频，甚至控制手机上的部分应用；也有人期待它能脱离手机独立使用。

背景是 OpenAI 2025 年 5 月以近 65 亿美元收购 Jony Ive 创立的硬件公司 io，当时奥尔特曼表示目标是打造一系列让人们用 AI 进行创作的设备。有报道补充称该设备由 Ive 团队主导设计，遵循"平静技术"（Calm Technology）的理念，无屏或极小屏、音频优先。需要提醒的是，发布时间、产量、芯片方案与量产时间目前都只是供应链层面的说法，尚无官方确认。

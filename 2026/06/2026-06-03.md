# 2026-06-03 AI 大事件

北京时间 2026 年 6 月 3 日（星期三）。这一天的主线是「入口」：一端是消费级 App 把 Agent 能力开放给第三方企业，另一端是微软第一次为「智能体优先」的设备做了一套独立操作系统。阿里千问 App 当天宣布向第三方 Agent、Skill 全面开放，瑞幸、肯德基、蜜雪冰城、东方航空成为首批在千问上测试品牌 Agent 的企业；同日，微软在 Build 2026 期间发布 Project Solara，底层不是 Windows 而是基于 AOSP 的 MDEP，并给出工牌与桌面终端两款概念参考设计。这两条线指向同一件事：智能体正在从「某个 App 里的功能」变成「平台的默认交互层」，而承载它的硬件形态也刚开始被重新设计。

> 本期记 2 条：千问向第三方 Agent、Skill 全面开放；微软发布 Project Solara 智能体设备平台。

## 1. 千问向第三方 Agent、Skill 全面开放：瑞幸、肯德基、蜜雪冰城、东航首批接入

6 月 3 日，千问 App 宣布向第三方 Agent、Skill 全面开放。官方给的说法是：企业不仅可以接入 Skill，还可以在千问 App 内运营自己的品牌 Agent，自定义 Agent 人设与具体服务边界，以对话形式向用户提供产品服务；公开报道显示，首批在千问上进行 Agent 服务测试、并将陆续上线的企业包括东方航空、肯德基、瑞幸咖啡与蜜雪冰城，其中瑞幸、肯德基、东航等已先以 Skill 形式在千问上提供到店自取等服务，企业侧的 Agent 与 Skill 接入平台计划于近期上线。

能力上的关键点是 Agent 不再只是被动应答。官方描述这类 Agent 具备记忆与主动规划能力，可在特定场景下主动提供服务，例如行程提醒、权益到期提醒、复购推荐。报道中引用的两个例子是：用户对着千问说「帮我在附近最近的肯德基门店，点一份 60 元以内的两人套餐，到店自取」，千问可以理解需求并推荐最合适的门店；等 Agent 形态升级后，东航 Agent 可在理解出行计划与旅行偏好后推荐行程方案，瑞幸 Agent 可主动提示「中午排队时间长，建议提前半小时点单」。这类设计把「搜索—下单」的一次性动作，替换成有记忆、有主动性的持续服务关系。

规模数字全部来自千问产品方口径，未见第三方核实。千问产品相关负责人称，过去半年千问 App 已陆续接入地图、打车、购物、闪购等数十个阿里生态 Agent，每天服务类对话上亿次；仅今年春节期间，就有超过 1.3 亿用户在千问 App 上体验过「Agent 办事」能力。官方同时表示，开放这些能力的目的是与各行各业共建 AI 时代的 Agent 服务生态，把千问做成一个更完整的个人助手。

值得记的是这一开放的性质：阿里把自家生态内积累的「需求理解—服务匹配—主动规划」能力对外开放接口，企业以品牌 Agent 的形式进入，用户不必更换入口。对行业而言，这是消费级 App 首次把 Agent 供给做成一套可被外部企业调用的平台能力，而不只是自己接入几十个服务。风险也在同一天可见：Agent 一旦具备记忆与主动推荐能力，推荐结果的解释、误推的追责、数据隔离的边界，都还没有可引用的行业规则。

## 2. 微软 Project Solara：不做手机的「智能体优先」操作系统

微软在 Build 2026 期间发布 Project Solara，一套从芯片到云、面向「智能体优先」设备的平台。底层不是 Windows，而是构建在 AOSP 之上的微软设备生态平台 MDEP，配套 Intune 设备管理、Entra ID 认证、Hello for Business 生物识别与硬件级麦克风静音键等企业能力。中文媒体在 6 月 3 日集中报道，英文站点发布时间标为美国 6 月 2 日，按本刊口径归入 6 月 3 日。微软资深技术专家 Steven Bathiche 的说法是，Project Solara 面向的是「智能体优先」的新型设备形态；微软同时表示该项目仍处于早期阶段。

台上给的是两款概念参考设计，都不是微软自己量产的产品。Badge Concept 是工牌形态：触摸屏、指纹传感器、远场麦克风阵列与扬声器、侧向摄像头，连接方式覆盖 WiFi、蓝牙、5G 与卫星，芯片方案来自高通的可穿戴产品线；它把企业工牌改造成常连的 AI 随行设备，护士、零售店员或办公室员工可以查看日程、录下当面谈话并自动转写，或直接向自己的 Agent 提问。Desk Concept 是桌面终端：触摸屏、双麦克风阵列、扬声器、UWB 存在感应，芯片方案来自联发科 IoT 产品线，用 Hello for Business 人脸识别做认证，通过 USB-C 接外部显示器后可直接作为 Windows 365 云 PC 客户端。两台设备的共同点是刻意不装传统应用——没有应用商店，没有以浏览器为前提的桌面。

最值得记的是交互范式。微软提出「just-in-time UI」：同一个 Agent 应当按当前设备自行改变呈现方式，在小屏上给一张只含单个动作的卡片，在桌面设备上给更完整的信息布局，接上大屏则生成仪表盘。开发者不必为每种形态重做一套界面。目前这一能力以自适应卡片等半结构化形式实现，微软明确表示完全生成式的 UI「还不在这里」，只是在响应式设计与不受限生成之间继续投入。平台既可承载微软自家的 Copilot、Researcher、Facilitator 以及新推出的 Priority Agent，也可通过 Microsoft 365 Agents SDK、Copilot Studio、Microsoft Agent Framework 接入第三方 Agent。

试点名单给出了第一批真实场景：数百名微软员工已在内部使用这两款概念设备，微软同时宣布与 AccuWeather、Best Buy、CVS Health、Levi's、Target 进行私有试点，GitHub Copilot 与医疗方向的 Dragon Copilot 正在探索 agent-first 形态。微软的赌注是，硬件按「智能体怎么工作」而不是「应用怎么工作」来设计，能让护理、零售等特定岗位拿到更合适的设备；未落地的是量产时间表与试点结果，微软均未公布。值得注意的是，在 Google、Salesforce、OpenAI 都在建 Agent 平台的时候，微软是第一个把同一概念做成一套既非手机、也非 PC、也非平板的专用操作系统与参考硬件的一方。

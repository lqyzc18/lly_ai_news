# 2026-03-07 AI 大事件

北京时间 2026 年 3 月 7 日（星期六）。Anthropic 与 Mozilla 联合公布：Claude Opus 4.6 在两周内为 Firefox 找出 22 个此前未知的漏洞，其中 14 个被 Mozilla 评为高危，约占该浏览器 2025 年全年高危修复量的五分之一。OpenAI 同日推出应用安全智能体 Codex Security（原 Aardvark），以研究预览形式向企业客户开放。国内一侧，阿里千问前负责人林俊旸在 7 日凌晨发朋友圈为自己在阿里的最后一天作别。

> 本期记 3 条：Claude Opus 4.6 与 Mozilla 的 Firefox 漏洞发现、OpenAI 推出 Codex Security、林俊旸发文告别阿里。

## 1. Claude Opus 4.6 找出 22 个 Firefox 漏洞，找漏洞比造漏洞便宜一个数量级

Anthropic 于 3 月 6 日（美国时间，周五）发布《Partnering with Mozilla to improve Firefox's security》，公布与 Mozilla 研究人员合作的细节。官方页面写明：Claude Opus 4.6 在两周内发现 22 个漏洞，Mozilla 将其中 14 个评为高危，"almost a fifth of all high-severity Firefox vulnerabilities that were remediated in 2025"。按月统计，Claude 在 2026 年 2 月发现的漏洞数量超过 2025 年任何单个月份由所有来源报告的总数。

测试的起点是一份自建评估。2025 年底，Anthropic 注意到 Opus 4.5 已接近解开 CyberGym 的全部任务，于是他们用 Firefox 过往的 CVE 构造了一个数据集来测试复现能力。Opus 4.6 能复现其中相当高比例的历史漏洞，但这引出了训练数据污染的疑虑——于是任务改成在当前版本的 Firefox 里找全新的漏洞。选 Firefox 的理由写得很直白：它既是复杂的代码库，也是世界上测试最充分、最安全的开源项目之一，每天有数亿用户依赖它。

进展速度是这组数字里最扎眼的部分。Claude 从 JavaScript 引擎入手，约 20 分钟就报告了一个 Use After Free（释放后使用）漏洞；一名 Anthropic 研究员在独立虚拟机中用最新 Firefox 复现后，又转给另外两名研究员各自验证。三人验证通过后，报告连同 Claude 写出的补丁一起提交到 Mozilla 的 Bugzilla。在验证和提交这第一个漏洞的期间，Claude 已经又发现了 50 个独特的崩溃输入。随后 Mozilla 研究员主动联系 Anthropic，建议不必逐个验证就批量提交——最后团队扫描了接近 6000 个 C++ 文件，提交 112 份独立报告。Mozilla 为此发布了 22 个 CVE。

漏洞分级是 14 高危、7 中危、1 低危。修复主要随 Firefox 148 发布（2 月 24 日），其余在后续版本修复。Mozilla 的安全公告 MFSA 2026-13 把 Anthropic 研究人员列为报告者，署名为使用 Claude 的七人团队。

Anthropic 随后做了另一组测试，想知道 Claude 能不能把漏洞变成可用的攻击工具。他们把已提交的漏洞交给模型，要求它为每个漏洞生成利用代码，并规定必须真的读写目标系统上的本地文件才算成功。跑了数百次、花掉约 4000 美元 API 额度后，Opus 4.6 只成功转化出两个可利用的漏洞。这带来两个结论：Claude 找漏洞远比造漏洞在行；找出漏洞的成本比造出利用低一个数量级。Anthropic 同时把这称为"令人担忧"——但强调这两个利用是粗糙的，只在刻意移除了沙箱等现代浏览器安全特性的测试环境里才有效。

方法论上最值得带走的是"任务验证器"（task verifier）。Anthropic 的经验是，模型在能自查自证时表现最好：给智能体一个可信的确认手段，让它实时判断自己的输出是否达成了目标。任务验证器既帮助了这次漏洞发现，在另一项独立研究中也被用于生成修复补丁。Anthropic 建议补丁智能体至少要验证两件事：漏洞确实被消除，以及程序原有功能没有被破坏。官方也明确说，通过这些测试的 AI 生成补丁不能假定为可直接合并，审阅时应当像对待外部作者的补丁一样严格。Anthropic 称已在 Claude Code Security 的有限研究预览中把这套发现与修复能力直接开放给客户和开源维护者，并表示已用 Claude Opus 4.6 在 Linux 内核等其他重要项目上发现漏洞。

## 2. OpenAI 推出 Codex Security：把漏洞发现做成企业开发栈里的一步

OpenAI 于 3 月 6 日（美国时间）发布 Codex Security 研究预览版。这个产品原名 Aardvark，自去年起在一小部分客户中私测，现在以研究预览形式通过 Codex 网页版向 ChatGPT Enterprise、Business 和 Edu 客户开放，首月免费。

定位是应用安全智能体。OpenAI 的出发点是：当前多数 AI 安全工具只会标出低影响发现和误报，逼着安全团队花大量时间做初筛；而智能体正在加速软件开发，安全评审反倒成了瓶颈。Codex Security 的做法是先把漏洞发现、验证和修复都嵌进系统自身的上下文里。

工作流程分三步。第一步是构建上下文并生成可编辑的威胁模型：扫描配置后，系统分析代码仓库的安全相关结构，产出一份项目专属的威胁模型，记录系统功能、信任边界和最易受攻击的环节，用户可以编辑它，让智能体与团队的评审标准保持一致。第二步是优先级排序与漏洞验证：以威胁模型为背景搜索漏洞，按预计实际影响分类；在条件允许时于沙盒验证环境压测，区分真实信号与噪声，并生成漏洞证明（PoC）。第三步是基于全系统上下文提出修复建议，确保补丁符合系统设计意图并把回归风险降到最低。用户调整某条发现的严重程度时，系统会用这反馈优化威胁模型。

数据都是 OpenAI 自己的口径。私测期间，同一代码仓库的持续扫描显示信噪比提升 84%，漏洞严重性虚标比例降低 90% 以上，全量代码仓库的检出误报率下降 50% 以上。过去 30 天里，Codex Security 在外部代码库扫描了超过 120 万次提交，识别出 792 项严重发现和 10561 项高危发现，严重问题只出现在不足 0.1% 的被扫描提交中。公司称已在 OpenSSH、GnuTLS、GOGS、Thorium、libssh、PHP 和 Chromium 等开源项目中报告严重漏洞，目前已分配 14 个 CVE 编号，其中两项为重复报告。此外 OpenAI 启动了"Codex for OSS"计划，为首批开源维护者提供免费的 ChatGPT Pro 与 Plus 账号、代码评审和 Codex Security，vLLM 等项目已把它纳入常规工作流。

对外部公司的意义在于打包方式。传统应用安全厂商面临的是捆绑问题：如果 OpenAI 和 Anthropic 把漏洞发现、验证和补丁建议都折进企业已经购买的开发环境，扫描市场的一部分就从独立品类变成"功能"。OpenAI 由此获得的还有更值钱的东西：关于企业软件如何被构建、评审和修复的遥测数据。NETGEAR 产品安全负责人 Chandan Nandakumaraiah 作为早期体验计划的背书称，Codex Security"明显提升了安全审计的效率与深度"。

值得注意的是竞争已经同步展开。Anthropic 在此前一个月已推出 Claude Code Security，OpenAI 的动作被 Axios 描述为前沿实验室与传统安全厂商之间的直接竞争。

## 3. 林俊旸发朋友圈告别阿里，最后一天

3 月 7 日凌晨，阿里千问（Qwen）前负责人林俊旸在朋友圈发文，为自己的阿里生涯作别。界面新闻的报道记录了他的原话："不是这几天，我都不知道这世界这么多人爱我。今天 last day，当大家为我鼓掌那一下，我真是忍住了泪水。不管别人说我什么，我至少内心里真觉得做到了为兄弟们好为阿里云好为集团好，虽然很多真没做到位，抱歉。"在评论区他又补充："为公司为千问，我只能做这么多啦，你们一定要加油啊！"

这是这场风波的第三个节点。3 月 4 日凌晨，他在 X 上发文宣布卸任，写的是"me stepping down. bye my beloved qwen."；同日 Qwen 后训练负责人郁博文、Qwen 3.5/VL/Coder 核心贡献者李凯新也透露离职，李凯新的告别帖写"从阿里 Qwen 签退。感谢与如此优秀的人共事，为我们的影响感到骄傲。继续前进！"，而 Qwen Code 负责人惠彬原此前已于 1 月离职加入 Meta。3 月 5 日上午，阿里 CEO 吴泳铭发出内部信批准辞职，由周靖人继续带领通义实验室，并成立由他、周靖人和范禹组成的基础模型支持小组；当晚阿里集团向媒体表示，千问模型团队稳定，没有出现"集体离职"的情况，所有产品与服务运行正常，基础模型团队从未被设置 DAU 等商业化 KPI。

外界对离职原因的解读仍不一致。据阿里内部人士对每日经济新闻的说法，随着千问从基模提升到集团整体战略，公司认为需要招揽更多技术人才、提升基模团队人才密度，这涉及到林俊旸原有权责范围的调整，多轮沟通后他不接受因而提出辞职；也有业内人士猜测与考核目标转向日活跃用户数有关。两种说法都未获阿里官方确认。

评价来自社区。Hugging Face 亚太生态负责人王铁震用"巨大损失"形容这次变动，艾伦人工智能研究院研究员 Nathan Lambert 称"如果 Qwen 倒塌，在开放研究生态中留下的巨大空缺将很难填补"。林俊旸 1993 年出生，本科就读北京大学计算机科学专业，硕士毕业于北京大学外国语学院，2019 年毕业后加入阿里达摩院，2022 年底通义实验室成立时被任命为通义千问系列大模型技术负责人。截至目前他尚未公布下一步职业规划。

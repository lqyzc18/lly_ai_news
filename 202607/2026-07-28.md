# 2026-07-28 AI 大事件

北京时间 2026 年 7 月 28 日（星期二）。今天最重的一条是基础设施：Model Context Protocol 在 2026-07-28 版规范正式定稿，把协议层的会话整个去掉——initialize 握手取消、Mcp-Session-Id 请求头删除，任何请求都可以落到负载均衡后面的任意服务实例上，这是 MCP 自 2024 年 11 月发布以来最大的一次修订。产业侧，《人民日报》用整个经济版版面记录人形机器人的量产现场：佛山南海的东方元启工厂年产能万台，配套的 0.2 毫米专用电工钢已做到量产。工具侧，GitHub 把 Copilot 做成一条从原型到代码审查的流水线；搜索侧，Similarweb 的统计显示 Google AI Overviews 一年内的出现率从 15% 涨到 43%。

## 1. MCP 2026-07-28 规范定稿：协议层取消会话

7 月 28 日，MCP 2026-07-28 规范正式发布，核心是把协议层的会话状态整体移除。2025-11-25 版要求每个客户端在调用任何工具前先发 initialize 握手、服务器返回会话 ID、后续请求都带上这个 ID；新规范取消了这一整套机制，协议版本、客户端信息与能力声明改为随每个请求在 `_meta` 字段内联传输，`Mcp-Session-Id` 请求头被删除（SEP-2575、SEP-2567）。维护者 David Soria Parra 与 Den Delimarsky 于 5 月 21 日锁定发布候选稿，随后开启 10 周验证窗口。

随之而来的有三项结构性变化。一是新增路由头（SEP-2243）：每个 Streamable HTTP 请求都带 `Mcp-Method`（如 `tools/call`）和 `Mcp-Name`（工具或资源名）两个 HTTP 头，负载均衡、网关与限流器不必解析请求体就能路由；规范要求服务器在头与请求体不一致时以 HTTP 400 加 JSON-RPC 错误 `-32020` 拒绝。二是客户端缓存（SEP-2549）：`tools/list` 等列表响应新增 `ttlMs` 与 `cacheScope` 字段，客户端据此决定结果可缓存多久、能否跨用户共享。三是扩展框架：Tasks 与 MCP Apps 以协商式扩展的方式提供，长耗时任务有 create/poll/cancel/resume 的正式生命周期，服务器返回的 HTML 面板可以在客户端内直接渲染。

被弃用而非删除的有三项：Roots 改由工具参数或配置传递，Sampling 改为服务器直接调用 LLM 厂商 API，Logging 改走 stderr 或 OpenTelemetry。新的生命周期政策（SEP-2596）保证从弃用到移除至少 12 个月，这三个能力在 2026-07-28 规范以及之后 12 个月内发布的任何规范版本中继续可用。另一个新增是多点往返请求（SEP-2322）：服务器可以中途暂停并要求客户端补充输入，返回 `resultType: "input_required"` 与 `inputRequests`，客户端用 `inputResponses` 重发原调用，状态随载荷走，因此任何服务实例都能处理这次重试——规范同时要求把 `requestState` 当作攻击者可控输入，凡是影响鉴权的地方都必须用 HMAC 或 AEAD 保护。发布当日起 TypeScript、Python、Go、C# 四个 Tier 1 SDK 全部支持新规范，Rust 版处于 beta。代价写在规范里：SSE 断流不再可用 Last-Event-ID 续传，断掉的流会丢失在途请求。

## 2. 人民日报整版记录人形机器人量产：年产能万台的工厂与 0.2 毫米电工钢

7 月 28 日，《人民日报》第 11 版刊发《带着上下游，人形机器人加速跑起来》，把镜头对准广东佛山南海区的东方元启智能机器人（广东）有限公司机器人工厂——由乐聚智能与广东东方精工联合打造，年产能万台的人形机器人规模化生产基地。

报道给出的量产难点相当具体。暨南大学人工智能教研室主任李德平说，人形机器人全身多关节相连，螺丝松紧等细微差别会被放大，导致行走与抓取出现明显偏差；行业零部件统一标准缺失，传感器与仿生配件配套不完善，不同机型还要单独调试运动与力度控制参数，规模化生产性能一致的产品难度很高。工厂的解法是柔性产线：手腿部、躯干、头部等关键部件在不同工位同步装配；重载型 AGV 跨区转运躯干与机架，轻载型 AGV 运送螺丝线缆传感器，顶升式 AGV 把托盘送到流水线高度；物料系统自动称重、计数、核对，一颗螺丝或一个垫片的变化都能被实时捕捉。乐聚智能助理副总裁曹雨说，只需在系统里切换生产指令，几分钟就能完成型号与配置切换，硬件只更换末端执行器与特定关节模组。产线末端每台机器人要过"上岗体检"：工作人员推撞机身看能否站稳、180 度转腰、复杂路面行走逐项校验，全部达标才通过考核。东方元启技术负责人总结得直接——"不在造得多、造得快，量产难在造得稳、造得一致"。

同一组报道把供应链往上游追了一段。河北迁安首钢智新的 0.2 毫米超薄人形机器人专用电工钢，厚度相当于发丝直径，研发团队做了 600 多次配方试验、10 余次工业验证、耗时一年，官方称相比常规产品铁损降低 20% 到 30%；首钢智新首席技术专家安冬洋给出的估算是每 1 万台人形机器人约用百吨电工钢。上海嘉定有企业做人形机器人的外衣与针织"皮肤"，后者正尝试在针织结构中植入导电纱线做压力感知。

## 3. GitHub Copilot 推出 Harness 工作流，app 升级为多 Agent 会话工作区

7 月 28 日，GitHub 在博客中发布 Copilot 的 Harness 工作流，目标是让开发者用单一工具走完原型设计、规划、实现到代码审查的完整链条。同日上线的还有 Copilot app 的升级：它被改造成多 Agent 会话工作区，支持同时管理多个互相独立的任务线程，每个会话可以绑定各自的项目上下文且进度互不干扰；用户可用 `/create-canvas` 在浏览器里启动 Canvas 预览界面，直接点选交互式 UI 元素做修改；新版本还引入 Agent Merge 功能，可自动响应 PR 审查反馈并处理合并冲突。

这两项发布的共同指向是"减少切换"。把原型、规划、编码、评审收进同一入口，是微软系这一年推工具的一贯路线；Copilot app 的多线程工作区则针对真实开发中很少只做一件事的现实，代价是上下文必须不串台。

## 4. Google AI Overviews 出现率一年从 15% 涨到 43%

据 Similarweb 7 月发布的生成式搜索领域分析报告（经 TechCrunch 报道），Google AI Overviews 在搜索结果中的出现率一年内从 15% 升至 43%，AI Mode 月访问量从 1.26 亿增至 2.79 亿。报告还记录了查询行为的变化：搜索词的平均长度持续增加，用户从短关键词转向更长的自然对话式提问。

对靠自然流量吃饭的网站，报告里最刺眼的数字是引用与点击的背离——过去一年 AI 回复中"包含引用来源"的数量增长超过 5 倍，但用户实际点进来源网站的比例没有同步增长；报告同时给出另一个方向的数据，截至 2026 年 5 月 7 日 ChatGPT 搜索更新后，其桌面端网页访问量占比从 3 月的 25% 翻倍多，到 5 月 30 日已接近 60%。这组数字来自 Similarweb 的第三方统计，不是 Google 官方口径。

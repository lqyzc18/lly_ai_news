## 1. OpenAI《Put AI to work》：把数百个企业落地案例的经验做成方法论

9 月 10 日 0 时 0 分（GMT），OpenAI 官方发布《Put AI to work: Lessons from hundreds of successful deployments》，换算成北京时间为当日 8 时，因此本篇归入 10 日。

这篇文章的形态值得注意：它不是产品发布，而是把数百个企业把生成式 AI 用进真实业务的过程中的经验做了一次归纳。对企业客户来说，模型能力和 API 文档早已不是问题，真正难的是"从哪里开始、怎么衡量效果、怎么让业务方真的用起来"——这类问题只能从大量落地案例里归纳。

这也解释了 OpenAI 为什么在这一阶段密集输出企业侧内容：随着 o1 系列推理模型的发布，模型能承担的任务复杂度上了一个台阶，"能不能用"的问题正在变成"怎么用才划算"。对咨询、系统集成与应用层创业公司来说，这篇文章相当于给出了一个统一的问题清单与评估口径。

另一个背景是这一周 OpenAI 连续发布多篇面向企业的材料（案例、部署经验、垂直行业案例），配合 9 月 12 日 o1 的发布，形成了一次面向 B 端的技术叙事推送。竞争压力是明确的：Claude 与 Gemini 在企业市场同样强调落地方法论，而 o1 这类"先思考再回答"的模型，在成本更高、需要重新设计工作流的前提下，更依赖方法论来证明性价比。

## 2. Kimi API 开放联网搜索

据 AIbase 9 月 10 日的每日 AI 日报收录，Kimi 智能助手旗下 API 推出联网搜索功能，开发者可以通过 API 获取互联网信息，从而提升交互体验。

联网搜索是这一阶段所有主流助手 API 的标准配置项，但它的意义不止于"能查资料"。搜索把模型从"训练语料截止日期"的时间限制里解放出来，也让企业可以在自己的系统里构造带时效性的服务——报价、库存、公告、赛事这类信息，离开联网就没有意义。

对 API 提供方来说，联网搜索也改变了成本结构：token 费用之外要叠加检索与抓取的费用，延迟也会明显拉长。这决定了它在产品设计里的位置——通常不是所有请求都默认开启，而是由调用方显式触发。

## 3. AI2 开源 OLMoE：70 亿参数的稀疏 MoE

据 AIbase 9 月 10 日的每日 AI 日报收录，AI2 发布全新开源模型 OLMoE，采用稀疏混合专家架构，总参数 70 亿，但每个输入 token 只激活其中一小部分参数，官方强调其"高效、强大且不再昂贵"。

稀疏 MoE 的商业逻辑很直接：把总参数做大以覆盖更广的知识面，同时让每次推理只调用少数专家，把实际算力开销压在远低于同等总参数稠密模型的水平。对于预算有限、又想在自己的数据上微调的团队，这种"大模型、小成本"的组合比直接调用商业 API 更容易长期负担。

AI2 一直强调开源模型的"可复现"属性——从数据、训练代码到训练过程数据都公开，这也是 OLMoE 这个系列被社区持续跟踪的原因：它同时是一个可用的小模型，和一份关于如何训练这类模型的技术记录。

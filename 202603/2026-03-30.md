## 1. 企业微信 CLI 开源：办公能力变成"可被 AI 调用的能力"

3 月 30 日，企业微信 CLI 开源项目上架 GitHub 社区，开放消息、日程、文档、智能表、会议、待办、通讯录七大核心产品能力，支持 Claude Code、Codex、WorkBuddy、QClaw 等主流 AI Agent 调用。

具体开放了什么：消息能力支持获取单聊、群聊消息，也可向指定用户和群聊发送消息；文档和智能表格支持新建、写入、读取；日程支持新建、查询、更新，并可查看闲忙状态、添加参与人；会议支持预定、查询、取消和添加参会人；待办支持创建、查询、添加参与人和更新状态；通讯录支持获取成员的 userid、姓名和备注信息。此次开源优先面向 10 人及以下企业，放的是一批高频能力。官方给出的接入方式是三步：先在企业微信后台创建机器人拿到 Bot ID 和 Secret，用 npm 安装 CLI 与 Skill，再执行一次初始化写入凭证（默认加密存储在 `~/.config/wecom/bot.enc`）。

理由说得很直接。对 Agent 来说，CLI 比传统接口更接近它的工作方式——不必反复处理复杂接口说明、不依赖 UI 适配，可以直接读取命令、执行任务并返回结果，更利于串联多步骤工作流，同时减少不必要的上下文消耗、压低 token 成本。企业微信自己的说法是：这次开源意味着它的核心办公能力正从"给人使用的功能"进一步变成"可被 AI 调用的能力"。企业微信也是腾讯产业互联网生态中率先拥抱 CLI 开源的企业服务软件。

## 2. 微软开源 VibeVoice：GitHub 一天 27K Star

微软开源了前沿语音 AI 模型家族 VibeVoice，涵盖语音识别（ASR）与文本转语音（TTS），项目刚上 GitHub 就登上趋势榜榜首。

三个模型分工明确。**VibeVoice-ASR-7B** 一次能处理长达 60 分钟的音频，输出的不只是文字，还包括"谁在说话""什么时候说的""说了什么"的结构化信息，支持 50 多种语言，适合会议记录、播客转录这类长音频场景。**VibeVoice-TTS-1.5B** 单次生成可达 90 分钟的连续音频，最多支持 4 个不同说话人进行自然对话模拟，能表现停顿、强调和情感转折。**VibeVoice-Realtime-0.5B** 面向实时场景，首音频输出延迟约 300 毫秒，同时能生成约 10 分钟的长语音，适合实时语音助手或直播配音。

技术底座是连续语音 tokenizer 加 next-token diffusion 框架。中文百科引述的细节是：连续语音分词器把 24kHz 采样率音频压缩到每秒 7.5 个令牌，对应高达 3200 倍的压缩率，从而在 64K 上下文窗口内合成长达 90 分钟、最多 4 名说话人的语音。许可采用 MIT 协议，支持本地部署，不需要云端订阅费用。

这里有一处值得记的插曲：项目曾因潜在误用风险被短暂下架，之后通过嵌入音频水印、可听免责声明等安全机制重新上线。权重可在 GitHub 和 Hugging Face 获取，社区已基于 VibeVoice-ASR-7B 做出名为 Vibing 的语音输入法等工具。

## 3. Runway Multi-Shot App：从"出素材"到"出成片"

据 AIbase 报道，Runway 推出 Multi-Shot App，把 AI 视频生成从单镜头制作推到全场景自动设计。用户只需输入一段场景描述，即可得到具有电影质感的完整短片。

核心是场景拆解与镜头规划：系统能把用户指令自动转化为最多 5 个逻辑连贯的镜头，同步完成构图、运镜、节奏控制与音效匹配，并按叙事节奏自动设置剪辑点。输入提供"图像起点"与"纯文本"两种模式——前者上传参考图后基于画面风格延伸生成完整故事，后者从零开始纯文字驱动。应用已在 Runway 网页端 App 抽屉上线。

被解决的是行业里一个具体的痛点：此前 AI 视频工具的输出基本是单条不超过 30 秒、缺乏连贯叙事的素材，要做一支完整短片得反复调试 prompt 生成多段素材，再手动拼接、调色、配音，光后期就可能耗掉普通创作者数小时。行业分析认为，这次更新的意义不止于"一键成片"这个功能，而在于它验证了 AI 可以替代视频生产流程中多个专业岗位的工作。

## 4. 蚂蚁 AI 安全实验室：三天提交 33 个 OpenClaw 漏洞报告

据央广网 3 月 30 日报道，蚂蚁 AI 安全实验室近期对开源自主智能体框架 OpenClaw 进行了专项安全审计，在为期三天的深度检测中共提交了 **33 个安全漏洞报告**。OpenClaw 已在最新发布的 2026.3.28 版本中确认并修复了其中 8 个，包括 1 个严重级别、4 个高危和 3 个中危漏洞。蚂蚁集团表示将持续关注 OpenClaw 的安全风险。

这条与 3 月 27 日 OpenClaw 在 GitHub 斩获 34 万星形成了一组对照：安装量越大，"养虾"这类本地智能体的安全面就越直接地暴露在公网上。同一时期 OpenClaw 社区还在推进 2026.3.28 版本的修复与发布。

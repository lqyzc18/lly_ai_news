# 2025-06-26 AI 大事件

北京时间 2025 年 6 月 26 日（星期四）。研究侧另有一条：苹果与香港大学合作的 7B 扩散代码模型 DiffuCoder 公开。开发者工具一侧有两条对照：OpenAI 宣布彻底放弃 TypeScript，用 Rust 重写 Codex CLI，并计划在其中开发一套"通信协议"让开发者用 TypeScript/JavaScript 与 Python 扩展它；谷歌则推出命令行工具 Gemini CLI，基于 Gemini 2.5 Pro，支持高达 100 万 token 的上下文窗口。版权与合规一侧，Getty Images 在伦敦高等法院撤回了对 Stability AI 的训练指控与输出指控，但次级侵权与商标指控仍在继续，美国的独立诉讼照旧；Scale AI 则被曝用公共谷歌文档存放客户机密，涉事文件一度可被任何人查看。

## 1. OpenAI 用 Rust 重写 Codex CLI，并计划加入"通信协议"

OpenAI 宣布将重构其 Codex CLI 工具，彻底放弃 TypeScript，转而采用 Rust 语言，目的是为开发者提供更高效、更稳定的 AI 终端交互体验。Codex CLI 最初是为简化开发者在终端与 AI 交互而设计的，采用了 TypeScript 和基于 React 的 Ink 框架；随着 Codex CLI 不断发展，团队发现 TypeScript 在应对日益复杂的用例时显得力不从心。

OpenAI 技术团队成员 Fouad Matin 在 GitHub 讨论中表示："我们正在重写 Codex CLI，采用 Rust 语言。"虽然 TypeScript 版本在快速原型开发中表现出色，但随着需求增加其局限性逐渐显现，OpenAI 决定完全替换 TypeScript 版本，未来将专注于 Rust 版本的开发。

Rust 带来的改善有三项：更好的安装体验，当前 TypeScript 版本要求 Node v22 及以上，这对部分用户是障碍；更好的安全性，Rust 能提供更可靠的本地绑定；更好的运行时性能，避免了运行时垃圾收集并降低内存消耗。

更值得注意的是后续计划：OpenAI 还计划在 Codex CLI 中开发一个"通信协议"，以便开发者可以使用多种语言（如 TypeScript/JavaScript 和 Python）扩展该工具。这意味着 Codex CLI 将不仅仅是一个工具，而是一个可扩展的多语言插件友好型运行时，为基于模型的自动化提供支持。目前 Rust 版本仍在开发中，但开发者反馈积极——有用户表示"原生 Codex 运行得非常顺畅"；TypeScript 与 Rust 版本之间仍存在配置文件支持及登录功能等差异，OpenAI 正有序解决，以尽快达到功能一致。

## 2. 谷歌发布 Gemini CLI：100 万 token 上下文，直击开发者终端

谷歌正式推出全新的命令行工具 Gemini CLI，基于谷歌自研的 Gemini 2.5 Pro 模型，旨在为开发者提供便捷的 AI 问答与内容生成服务。借助该工具，开发者可以在自己的终端界面中直接调用 AI 的能力，从而提升编程效率与工作便捷性。

它最显眼的一项指标是上下文窗口：Gemini CLI 支持高达 100 万个 token 的上下文窗口，这意味着模型可以处理大量信息。同时，Gemini CLI 与谷歌的 Gemini Code Assist 代码助手进行了深度整合，内置的模型上下文协议（MCP）和谷歌搜索功能进一步增强了工具的实用性。

应用场景并不限于编程，还可以广泛应用于内容生成、任务管理和问题解决等领域，谷歌称该工具的推出将丰富开发者的工作方式。当前 Gemini CLI 正在进行预览，开发者只需通过个人谷歌账户即可获取免费的 Gemini Code Assist 使用许可证，但配额有限：每分钟最多 60 次请求，每日最多 1000 次请求。谷歌尚未透露未来是否会收费，以及超出配额后的收费标准。

把 100 万 token 上下文与免费额度放在一起看，这更像一次用户获取动作而非单纯的功能发布——命令行工具的安装成本本来就低，先把规模做起来，再谈商业化。

## 3. Getty Images 撤回对 Stability AI 的核心指控，英国诉仍在继续

Getty Images 公司在伦敦高等法院宣布，已撤回对 Stability AI 的主要版权侵权指控，使得这场备受关注的法律斗争进一步缩小了焦点。此次诉讼的核心是关于 AI 公司如何使用受版权保护的内容来训练其模型。

Getty Images 于 2023 年 1 月起诉 Stability AI，声称后者在未获授权的情况下使用了数百万张受版权保护的图像来训练其 AI 模型；盖蒂还表示 Stable Diffusion 生成的许多作品与其受版权保护的内容相似，甚至有些作品上带有其水印。此次撤诉中，Getty Images 已撤回了训练指控和输出指控。

法律专家给出的解释是，Getty Images 可能因未能证明侵权行为与英国版权法的关联而放弃了训练指控，而输出指控则因无法证明生成内容构成其图像的实质部分而被撤回。在结案陈词中，公司律师表示撤回这些指控是出于证据不足以及 Stability AI 缺乏知情证人的考虑，目的是让案件更集中于更有胜算的指控上。诉讼中保留的内容包括次级侵权指控与商标侵权指控——次级侵权指控认为，AI 模型本身可能侵犯版权法，而在英国使用这些模型可能构成进口侵权产品的行为，即使训练是在英国以外进行的。

Stability AI 回应称对 Getty Images 撤回多项指控感到欣慰，并认为商标和虚假宣传指控将无法成立，因为消费者不会将水印视为 Stability AI 的商业信息。在美国，Getty Images 同样对 Stability AI 提起了商标和版权侵权诉讼，索赔金额可能高达 17 亿美元；Getty 的发言人表示撤回在英国的版权诉讼并不影响其在美国的案件进展。这条消息还恰逢美国法官在一类似争议中支持 Anthropic，认为在没有作者许可的情况下对书籍进行 AI 训练并不违反版权法。

## 4. Scale AI 被曝用公共谷歌文档存放客户机密，涉事文件一度人人可查

近期人工智能初创公司 Scale AI 陷入一场严重的数据安全风波。这家估值不菲、并被 Meta 以 148 亿美元收购 49% 股份的公司，被曝出竟然使用公共的谷歌文档来存储包括 Meta、谷歌和 xAI 在内的众多客户的绝密信息。谷歌文档的"邀请或完全公开"共享方式，显然与任何公司的严格安全标准格格不入；据报道，任何知道 Scale AI 文档链接的人都可以轻易访问这些包含绝密项目、电子邮件地址和付款信息等敏感内容的文档。

据五名 Scale AI 的承包商透露，谷歌文档在 Scale AI 内部被广泛使用。Scale AI 的一位发言人回应称，公司正在进行彻底调查，并且已经禁止任何用户公开分享 Scale AI 管理系统中的文档；谷歌和 xAI 尚未评论此事，Meta 则拒绝置评。网络安全专家指出，尽管目前尚无迹象表明这些公开文件已导致实际数据泄露，但这种存储方式无疑让 Scale AI 极易受到黑客攻击。

泄露的范围相当具体。调查显示，在 Scale AI 采取措施之前，人们可以查看多达 85 份、数千页的项目信息，其中详细记录了公司与大型科技客户之间的敏感合作。例如，这些文档揭示了谷歌如何利用 OpenAI 的 ChatGPT 微调自己的聊天机器人；至少有七份被标记为机密信息的谷歌项目手册向公众开放，其中包括改进 Bard 的具体建议；公开文档中甚至包含马斯克"木琴计划"（Project Xylophone）的详细内容，比如用于训练 xAI 模型的 700 个对话提示。承包商还透露，尽管项目通常有秘密代号，他们仍能清晰辨别自己服务的是哪个客户；使用 AI 产品时，聊天机器人有时在被询问时甚至会直接透露客户信息。

除了客户机密，文档中还披露了 Scale AI 数千名员工的姓名和私人联络方式，有些文件甚至详细列出了个体承包商的工资金额，包括工资纠纷与差异的说明。

## 5. Anthropic 升级 Artifacts：可直接在 Claude 中构建并分享 AI 应用

Anthropic 宣布推出名为 "Artifacts" 的新功能，允许用户创建个性化应用程序，通过简单的对话进行创作而无需任何编程知识。Artifacts 功能最初于去年六月推出，并在八月向所有用户开放：用户可以在对话窗口旁边的独立区域中展示创作的各种对象，如图片和图表，这些输出被保存在系统记忆中形成独立对象，可在不同会话中持续访问和使用。

最新公告中，Artifacts 的展示方式得到改进：用户现在可以在一个独立的仪表盘上管理和分享自己的创作，还可以浏览其他人制作的精选应用，这些应用被整理在一个专门的区域。Anthropic 提到早期用户已经创建出各种智能应用，如能自我思考的游戏、智能辅导员，以及用简单语言回答数据分析问题的工具；官方展示的示例包括具有独立节拍控制的鼓机应用、让玩家在森林中探险的第一人称游戏，以及一个打击彩色方块的横版游戏。

Anthropic 的意图是打造一个类似应用商店的平台，促进用户之间的共享与合作，任何拥有 Claude 账户的用户（包括免费账户）都可以自由访问这些应用。共享功能也契合其最初的设计理念——促进团队协作，公司同时推出了针对团队的使用计划。

## 6. 苹果与港大：DiffuCoder，7B 扩散语言模型写代码

DiffuCoder 是苹果与香港大学合作训练的 7B 扩散大语言模型（dLLM），用于代码生成。基座是 Qwen-2.5-Coder，训练用 1300 亿有效 token。论文 v1 提交于 6 月 25 日（美东 6 月 25 日 13:35），arXiv 于美东 6 月 25 日 20:00 公告公开，对应北京时间 6 月 26 日 8 时，故本条归 6 月 26 日；模型权重与代码由苹果于 7 月 1 日在 GitHub 放出，中文媒体 7 月 4 日至 5 日跟进报道。

训练分四个阶段：适配式预训练、以 160 亿 token 代码退火数据做中间训练（退火期）、用 OpenCoder 的 43.6 万条 SFT 样本做指令微调，以及后训练的强化学习。最后一步引入了团队自研的耦合-GRPO（Coupled-GRPO），在两个互补的掩码视角下评估每个 token 的概率，采样效率翻倍，开销增长不大。指令微调后的模型在 EvalPlus 上有 4.4% 的提升。

研究里提出一个新指标「自回归度」（AR-ness），用来量化扩散模型解码时是否还留着从左到右的顺序偏好。结论有几条：dLLM 能自主调节生成过程的因果性，不需要半自回归解码；采样温度不仅影响选哪个 token，还会改变 token 的生成顺序；代码任务比数学任务更能激发「去顺序化」的生成方式；不过局部和全局 AR-ness 都仍然接近 1，说明文本本身有顺序结构。论文还观察到首步解码的置信度分布呈「L」形，作者称之为「熵汇集」（Entropy Sink）。团队也承认，dLLM 在指令微调阶段的增益远不如自回归模型，指令对齐仍有差距。

一作是香港大学博士生 Sansa Gong，导师 Lingpeng Kong，本科硕士均毕业于上海交通大学。除苹果的 Navdeep Jaitly 外，作者都是华人。

# 2026-04-02 AI 大事件

北京时间 2026 年 4 月 2 日（星期四）。Anthropic 的 Claude Code 在 3 月 31 日因打包配置失误，把约 51.2 万行 TypeScript 源码发到了 npm 上，公司随后用 DMCA 要求 GitHub 下架 8100 个仓库，误伤了大量无关仓库，4 月 1 日紧急撤回了大部分请求。同一时间，社区用净室重写绕开版权，替代项目 claw-code 两小时内涨到 5 万星标。谷歌在 4 月 1 日推出低价视频模型 Veo 3.1 Lite，宣布 4 月 7 日下调 Veo 3.1 Fast 全线定价。国内方面，20 人团队 Genspark 的 B 轮与估值数字在 4 月 2 日被国内媒体集中报道。

## 1. Claude Code 源码泄露：51.2 万行与 8100 个被误删的仓库

3 月 31 日 14 时，Anthropic 在 npm 发布 @anthropic-ai/claude-code v2.1.88，把包含完整源码的调试用 cli.js.map 一并打包进去，文件约 59.8MB，其 sourcesContent 字段保留了未混淆的 TypeScript 源码。据安全公司 Fuzzland 实习研究员 Chaofan Shou 披露，他在当天 16 时 30 分左右发现问题并在 X 公开了存储桶的直接链接，涉及约 1906 个源文件、51.2 万行代码。

根因不在入侵，而在发布流程。打包器默认生成 Source Map，Anthropic 的流程里没有任何一步把它排除掉，.npmignore 与 package.json 的 files 字段都没有相应设置，Source Map 又直接指向 Anthropic 自有 Cloudflare R2 存储桶中公开可访问的 ZIP 包。公司向 VentureBeat 确认这是"人为失误引发的发布打包问题"，并表示正在采取措施防止重演。

公司随后依据美国《数字千年版权法》向 GitHub 提交版权投诉，GitHub 配合执行，超过 8100 个仓库被禁止公开访问，其中包括 Anthropic 自身开源项目的正常分支。4 月 1 日，Claude Code 负责人 Boris Cherny 承认误操作，撤回大部分下架请求，只保留对 1 个仓库和 96 个分支的处理，GitHub 随后恢复了多数受影响仓库的访问权限。他的说法是这是一个本应自动化、却以手动方式完成的部署步骤，团队正着手改进自动化流程。

Anthropic 确认此次泄露未涉及用户数据、凭据、模型权重或推理基础设施，核心 Claude 模型未受影响。公司还提醒：3 月 31 日协调世界时 00:21 至 03:29 期间，npm 上同时发生了针对 axios 套件的供应链攻击，在该窗口内安装或更新过 Claude Code 的开发者应审查依赖并轮换凭据，未来优先使用官方原生安装程序而非 npm。这不是首次。2025 年 2 月 Claude Code 早期版本发生过几乎一样的 Source Map 泄露，公司当年 4 月提交过首份 DMCA 通知；3 月 26 日（3 月 27 日）Anthropic 又因 CMS 配置错误公开了约 3000 份内部文件，其中包含未发布模型 Claude Mythos 的细节。五天内两度泄露，被广泛质疑的是流程而不是某一个人的失误。

## 2. claw-code：净室重写与"永不下架"的镜像

泄露之后，最快的应对不是修复，而是重写。韩国开发者 Sigrid Jin 在 3 月 31 日凌晨用 Python 从零实现了一套功能相近的系统，命名为 claw-code，推上 GitHub。据智东西 4 月 1 日报道，该仓库发布两小时突破 5 万星标，创下 GitHub 历史上最快纪录；后续报道给出的数字是星标接近 10 万、fork 超过 9 万，fork 数一度反超星标数。

重写方式的关键是"净室"（clean-room）：不复制也不粘贴原始 TypeScript 代码，只依据对产品功能的外部观察重新实现，在法律上构成全新创作。开发者社区随后用 Rust 做了高性能重构版本，并衍生出多模型切换、本地部署、自定义工具集等分支。Anthropic 的 DMCA 覆盖的是原仓库及其 fork 网络，对没有原始代码的重写版本难以适用。

扩散也绕开了中心化平台。去中心化 Git 平台 Gitlawb 把完整源码做了镜像，并在 X 上公开表示"永远不会被下架"。这件事把一个版权问题变成了平台治理问题：DMCA 之所以对 GitHub 有效，是因为中心化平台有合规义务、有单点可施压，去中心化基础设施不存在这个单点。

泄出的内容本身也值得记一笔。暴露出的约 1900 个文件涵盖工具执行逻辑、权限架构、记忆系统、遥测和功能开关，其中包含名为 KAIROS 的后台守护进程（监视文件、记录事件，并在空闲时执行名为 Dreaming 的记忆整合流程）、名为 BUDDY 的终端宠物功能、COORDINATOR MODE（单代理生成并管理多个并行工作代理）、ULTRAPLAN（10 至 30 分钟的远端多代理规划会议）等未发布功能，共 44 个功能开关。快思慢想研究院院长田丰在接受《科创板日报》采访时把这次事件称作"被动开源"而非主动开放，并强调国内团队应借鉴架构而非直接复制代码，以规避法律风险。

## 3. 谷歌 Veo 3.1 Lite：720p 每秒 0.05 美元，4 月 7 日 Fast 同步降价

谷歌 4 月 1 日推出 Veo 3.1 Lite，定位为 Veo 3.1 系列中成本最低的视频生成模型，生成速度与 Veo 3.1 Fast 相同。定价为 720p 每秒 0.05 美元、1080p 每秒 0.08 美元，按时长计费，可选 4 秒、6 秒或 8 秒；支持文生视频与图生视频，横竖屏 16:9 与 9:16，默认包含音频生成。

对照差距：生成一段 8 秒 720p 视频，Lite 约需 0.40 美元，Veo 3.1 Fast 按当时 0.15 美元/秒计约需 1.20 美元，成本约三倍。谷歌的说法是让开发者能以不到 Fast 一半的成本构建高容量视频应用。功能上 Lite 不支持 4K 输出，也不支持视频延长，最长 8 秒。

谷歌同时宣布 4 月 7 日起下调 Veo 3.1 Fast 的定价。720p 从 0.15 美元/秒降至 0.10 美元/秒，这一条各家口径一致；1080p 与 4K 的调降后价格，各家转述并不一致——BlockBeats 记为 1080p 降至 0.12、4K 降至 0.30，环球网转述则写成 1080p 降至 0.15、4K 降至 0.35，与调价前的数字相同。以调价前 Fast 的 1080p 0.15、4K 0.35 为起点，BlockBeats 的版本更自洽。

Veo 3.1 Lite 已通过 Gemini API 与 Google AI Studio 的付费层开放，普通用户无法在 Gemini 应用中体验。发布时点与 OpenAI 关停 Sora 视频应用相邻。

## 4. Genspark：B 轮 3.85 亿美元，投后估值约 16 亿美元

据 4 月 2 日国内媒体（钛媒体旗下胖鲸头条，经富途转载）报道，Genspark 于 3 月 13 日宣布 B 轮融资扩展至 3.85 亿美元，投后估值约 16 亿美元，约合 110 亿元人民币。数字本身早于本日，4 月 2 日是国内媒体把它系统写出来的一天。

公司由前百度高管景鲲与朱凯华创立。两人在百度共事 11 年，共同打造了估值近 50 亿元的小度生态；景鲲此前任微软首席研发总监，朱凯华曾任谷歌主任架构师、百度智能助手首席架构师与小度 CTO。团队规模约 20 人，持 37 项专利。

商业数据同样来自公司口径：截至 2026 年 3 月，年经常性收入（ARR）达 2 亿美元（约 13 亿元人民币）；付费转化率约 35%（报道给出的行业平均约 8%），毛利率超 65%，付费用户留存率 88%–92%。2026 年 1 月日本市场月访问量突破 1496 万次，环比增长 22%；产品入选 a16z《Top 50 Gen AI Apps》榜单，Web 端第 47 位。产品形态是 All-in-one 工作空间，以 MoA 多智能体混合架构做端到端自动化，跑在云端而非本地。

测评部分是公司与媒体的混合口径：公司称在 GAIA 测评中综合表现超过 OpenAI Deep Research 与 Manus，Level 3 高阶任务完成率 58.8%，事实核查准确率 98.2%；但报道中引用的第三方测评评价其"现阶段更像一名初级实习生"，并指出复杂任务响应偏慢、排版死板。这两套评价指向的是同一款产品的两端。

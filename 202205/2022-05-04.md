## 1. GitHub 宣布 2023 年底前要求所有代码贡献者启用 2FA

GitHub 首席安全官 Mike Hanley 在官方博客中宣布，到 2023 年底，所有在 GitHub.com 上贡献代码的用户都需要启用至少一种形式的双因素身份验证（2FA），才能继续使用该平台。博客原文写的是「今天（5 月 4 日）」，页面时间戳为美东时间 5 月 4 日上午 8 时 04 分，换算成北京时间是当日 23 时 04 分。

驱动因素是开发者账户被接管。2021 年 11 月，一批未启用 2FA 的开发者账户遭到入侵，导致多个 npm 包被恶意接管，GitHub 随后承诺在 npm 账户安全上持续投入。Hanley 在博客中的原话是「软件供应链的最上游就是开发者……保护开发者免受这类攻击，是确保供应链安全的第一步，也是最关键的一步」。他还写道，被入侵的账户可用于窃取私有代码或推送恶意改动，对相关代码的拥有者和使用者都构成风险，潜在影响会沿着更广泛的软件生态与供应链向下传导。

采用率是这次公告的关键数字。GitHub 的内部研究表明，目前只有大约 16.5% 的活跃用户（大约六分之一）对其账户启用了增强性的安全措施，npm 用户中启用 2FA 的比例是 6.44%。此前 GitHub 已在一小部分用户上强制 2FA：2022 年 2 月起要求 npm 前 100 个软件包的维护者启用，3 月起把全部 npm 账户升级为增强登录验证，并计划在 5 月 31 日把强制范围扩大到前 500 个软件包的维护者，最后一批是高影响力软件包的维护者（依赖超过 500 个，或每周下载量 100 万次以上），计划在当年第三季度完成。GitHub 表示会在接下来几个月公布在 GitHub.com 上强制 2FA 的细节与时间表，把目标定在 2023 年底是为了留出足够时间优化体验，也继续探索无密码验证等新方式。

Hanley 在接受 The Verge 采访时表示，GitHub 在软件开发生态中处于一个独特位置，凭 GitHub.com 上绝大多数开源和创作者社区，可以通过提升最低账户保护标准整体提高这个社区的安全性。

# 2022-11-04 AI 大事件

北京时间 2022 年 11 月 4 日（星期五）。一条法律消息：开源程序员 Matthew Butterick 与 Joseph Saveri 律所在旧金山北区联邦法院对 GitHub、其母公司微软以及 OpenAI 提起集体诉讼，指控 GitHub Copilot 违反开源许可证条件不当获利。

> 本期记 1 条：GitHub Copilot 遭首宗「AI 训练方式」集体诉讼。

## 1. 诉状的核心指控：把开源代码当公有领域

起诉时间是美国时间 11 月 3 日，新闻稿由 Joseph Saveri 律所在旧金山发布，案件提交美国加州北区联邦地区法院。原告方是 Butterick——一位律师、设计师兼程序员，与 Joseph Saveri 律所合作，代表「开源程序员」这一群体提起集体诉讼；被告方是 GitHub、其母公司微软，以及其 AI 技术合作方 OpenAI。

诉状中 Butterick 的表述很直接：GitHub Copilot 是一个由 GitHub 与 OpenAI 合作打造、基于 AI 的产品，看起来是靠侵食开源程序员的作品获益。诉状写明，「通过在公开的 GitHub 仓库上训练他们的 AI 系统（依据他们的公开表述，可能远不止这些），我们主张被告侵犯了大量创作者的法律权利——这些创作者把代码或其他作品以某些开源许可证发布在 GitHub 上。」

具体到技术细节，指控有三条：Copilot 生成的代码不包含任何原作者署名、版权声明或许可证副本，而多数开源许可证都要求保留这些；诉状列出 11 个可能被违反的流行开源许可证，包括 MIT、GPL 与 Apache 许可；并援引《数字千年版权法》第 1202 条——该条禁止删除版权管理信息。诉状的原话是，Copilot「忽视、违反并抹去了成千上万——甚至数百万——软件开发者的许可证，从而以空前的规模完成软件盗版」。

## 2. 一场早已公开的争论终于进了法庭

这不是一次突袭。Butterick 在 2022 年夏天就写过一篇题为《This Copilot is Stupid and Wants to Kill Me》的博客文章，详细说明自己为什么要站出来。Copilot 2021 年 6 月以有限技术预览发布时，开源社区就开始质疑它的训练方式；这次诉讼把持续了一年半的争论搬进了法庭。

微软方面的法律立场此前也有公开表述。前 GitHub CEO Nat Friedman 在 2021 年的推文中给出两条一般性原则：在公开数据上训练机器学习系统属于合理使用；输出归运营者所有，就像编译器一样。但软件自由保护协会主任 Bradley M. Kuhn 在 2022 年 2 月的博文里指出，微软与 GitHub 代表曾私下被要求提供支持其公开法律立场的坚实法律依据，而他们没有提供，只是重申相信模型不包含软件的副本、Copilot 的输出可以按任何许可授权使用。Kuhn 还追问了一个直指要害的问题：既然双方都认为不存在许可层面的顾虑，微软为什么没有在自己的 Office 等专有代码库上训练这个系统？

Butterick 在接受采访时把这件事类比为 Spotify 与 Apple Music 之于 Napster：一旦过了 AI 的「Napster 阶段」，创作者会被请到桌前谈判，规则会重新确立。

## 3. 被告的回应与「合理使用」之争

GitHub 给出的回应是：「我们从一开始就承诺以负责任的方式创新 Copilot，并会继续演进产品，以为全世界的开发者提供最好的服务。」公司同时表示，计划推出一项新功能，为那些与 GitHub 上的公开代码相似的建议提供参考，以便开发者能更明智地决定是否以及如何使用这些代码，并在适当时提供署名；GitHub 也已提供可配置的过滤器，用于拦截与公开代码匹配的建议。

诉讼同时把矛头指向了微软《About GitHub Copilot》页面上的免责表述：用户需要自行确保 Copilot 生成代码的安全性与质量，建议采取与使用自己写的代码相同的防护措施，包括严格测试、知识产权扫描和漏洞追踪。Butterick 把它读成微软在把责任推给使用者。

争议的技术核心至今没有定论。原告方主张 Output 往往近乎逐字复现训练数据中的代码，Codex「没有经过训练去提供归属信息」，输出不包含版权声明或许可条款——而这是设计使然。被告方则以合理使用抗辩，认为 Copilot 的建议具有转化性，且大多数建议与训练数据并不实质相似。

Butterick 说这是美国第一起挑战 AI 系统训练与输出的集体诉讼，并写道：「AI 系统并不豁免于法律。那些创造和运营这些系统的人必须继续承担责任。如果微软、GitHub 和 OpenAI 这样的公司选择无视法律，就别指望我们公众会坐着不动。」

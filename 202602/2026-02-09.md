# 2026-02-09 AI 大事件

北京时间 2026 年 2 月 9 日（星期一）。本期记 3 条。Anthropic 的一项随机对照试验给出不太舒服的结论：把 AI 当自动完成工具的开发者，在新技能掌握度测试中得分低 17%。Claude Code 推出「快速模式」预览版，官方称 Opus 4.6 的响应延迟因此显著下降。算力侧的两条消息指向同一个矛盾——英伟达在 HBM4 上排除美光、锁定海力士与三星，而纽约州议员正提议暂停 3 年发放新的数据中心许可证。

## 1. Anthropic 研究：过度依赖 AI 辅助的开发者，技能测试得分低 17%

Anthropic 发布一项关于 AI 辅助如何影响编程技能形成的研究，采用的是 52 名软件工程师的随机对照试验设计，目标是量化 AI 辅助对技能学习的影响。

结论有三点。第一，过度依赖 AI 辅助的开发者，在新技能掌握度测试中得分低 17%。第二，关键变量不是用不用 AI，而是怎么用：把 AI 当作「自动完成工具」直接复制粘贴的人表现最差。第三，主动提问、寻求解释、在独立编码时提出概念性问题的人，技能保留几乎不受影响。

研究给出的解释框架是——AI 应该是思考的放大器，而不是替代品。真正的损失发生在开发者把「写出能跑的代码」当成目标、跳过了理解与推演过程的时候；一旦 AI 取代了判断，技能的增量就不再发生。

这项研究的时间点有意思：就在两周前，Anthropic 自己发布 Opus 4.6 时给出的论证是「编程正在从写代码转向编排写代码的智能体」，而同一份材料里也提到了 52 人规模的研究。两句话指向同一个张力——如果工程师的角色确实转向编排，那么「保留手写技能」这件事的前提就变了。

## 2. Claude Code 快速模式预览上线，Opus 4.6 响应延迟显著下降

Claude Code 推出「快速模式」预览版。据 IT 之家援引官方说明，这一模式通过优化 API 配置显著降低 Claude Opus 4.6 的响应延迟，且不影响模型质量。该模式面向订阅用户开放，按额外用量计费。

同一时间，Anthropic 披露的一组数字说明了 Claude Code 在开发者生态里的实际位置：Claude Code 目前贡献了 GitHub 公开提交的 4%，并有望在 2026 年底前超过每日提交总数的 20%。Anthropic 另称 Opus 4.6 几乎无需任何提示，就在开源库中发现了 500 多个此前未知的高危安全漏洞。

需要区分的是，这里的 4% 是公开提交中的占比，不等于「GitHub 上四分之一的代码由 AI 写」。Anthropic 同时称目前拥有超过 30 万家企业用户。

## 3. 算力供应链的两面：HBM4 排除美光，纽约州拟暂停数据中心许可

供给侧的调整在英伟达这一侧。据每日 AIGC 早报 2 月 9 日的汇总，在 HBM4 高带宽显存的供应商选择上，英伟达排除了美光，锁定海力士与三星，二者供货份额分别约占 70% 和 30%。另一侧的记录则显示，由于 HBM 持续紧缺，英伟达可能放弃 2026 年新一代消费级游戏显卡的发布，把存储芯片配额优先给数据中心与 AI 业务线。

需求侧则出现政策收紧的信号。纽约州参议员和众议员提出暂停 3 年发放新数据中心许可证的议案，超过 230 个环保组织也支持全国性暂停。同一份早报还记录了另一组财务数字：财报显示亚马逊、谷歌和微软云计算收入的积压总额达 1.1 万亿美元，其中微软高达 6250 亿美元。

这三条放在一起是同一个矛盾的不同侧面：算力需求仍在加速，而承载它的两个稀缺资源——存储芯片和电网容量——正同时收紧。
